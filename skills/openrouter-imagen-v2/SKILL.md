# 出图与改图

这个技能教你**怎么把用户的话变成一条能用的提示词**。画由生图模型完成，你只做两件事：听懂需求，写提示词。

## 你的职责只有两件事

1. **听懂需求** —— 用户想要什么画面。
2. **写出一条专业提示词** —— 然后用 `openrouter_generate_imagen_v2` 出图。

**不要复述参考图里已经拍清楚的外观。** 生图模型自己会读参考图（它走 `input_references`，不是文本）；再从文字里描述一遍产品外形、颜色、logo、端子、结构，只会与图像本身打架、降低还原度。要锁住主体就写一句「保持参考图中的产品外观不变」。

**不要用文字代替出图。** 用户要图就给图。给出提示词不等于交付。

## 第一步：照用户说的媒介写

他说水彩就是水彩，说赛璐璐就是赛璐璐 —— **不要先归类再翻译**，也不要往固定几类里硬塞。

## 第二步：定媒介，然后推出它的轴

不要查表，要**推导**。两步提问：

**问：这种媒介靠什么被认出来？**
认得出它的那几个特征，就是你要写的轴。线条？笔触？材质？色块？像素网格？光影？墨色层次？

**问：它没有什么？**
不属于它的轴一律删掉。卡通没有焦段光圈，照片没有描边上色，像素画没有抗锯齿和渐变，水墨没有饱和彩色。

**然后用它自己的词汇写。**

### 几个示范（不是清单）

| 媒介 | 靠什么被认出来 | 没有什么 |
| --- | --- | --- |
| 商业摄影 | 光线方向与质感、镜头与景深、色彩与影调、材质 | 描边、平涂色块 |
| 线条图 / 图标 | 线宽、线条粗细对比、负空间、单色 | 焦段光圈、光影层次 |
| 扁平矢量 / 卡通 | 大色块、圆角线条、有限调色板、大头比例 | 焦段光圈、柔光箱、写实材质 |
| 水彩插画 | 水痕与晕染、纸纹、透明叠色、留白 | 硬边、写实景深 |
| 像素画 | 网格尺寸、调色板数量、抖动、无抗锯齿 | 抗锯齿、渐变、写实细节 |

### 两个表外的推演示范

> 用户：「国风水墨的山水」
> 靠什么被认出来：墨色浓淡层次（焦/浓/重/淡/清）、留白与虚实、皴法笔触、散点透视。
> 没有什么：焦段光圈、柔光箱色温、描边、饱和彩色。
> → `Traditional Chinese ink-wash landscape on xuan paper, layered ink tones from dense black to pale wash, dry-brush cun strokes for rock texture, vast empty space for mist and water, scattered perspective with no vanishing point, monochrome with a single faint vermilion seal, no outlines, no saturated color.`

> 用户：「蒸汽波风格的海报」
> 靠什么被认出来：霓虹渐变（品红/青）、网格地平线、罗马雕塑与棕榈剪影、80 年代电脑字体、扫描线。
> 没有什么：自然光、写实材质、手绘笔触。
> → `Vaporwave poster, neon magenta-to-cyan gradient sky, perspective grid horizon, classical bust and palm silhouettes, chrome 80s computer type, scanlines and VHS grain, saturated synthetic palette, no natural light, no hand-painted texture.`

### 唯一的硬规则

**焦段、光圈、柔光箱、色温是摄影与照片级 3D 的器材与布光。** 写进卡通、线稿、水墨、像素画里只会把画面拽向照片。

注意区分：**「光线」不是摄影专属，但「布光」是。** 任何画风都能把光写成*画面内容*（「晨光穿过树间」「烛光下的暖调」）；写成*器材与布光*（`85mm f/1.4, softbox key light`）才是摄影。

## 第三步：缺的槽位，你自己补

用户不会说全。缺的部分按该媒介的专业默认值补上，**不要反问** —— 反问他只会得到「你看着办」。

| 用户说的空词 | 换成具体参数 |
| --- | --- |
| 高级 / 有质感 | 低调布光、大面积留白、f/8 全清晰、哑光材质 |
| 可爱 | 大头比例、圆角线条、暖色、高饱和、简单背景 |
| 大气 | 广角、低机位、强对比、大留白、单一光源 |
| 干净 | 极简构图、单一主体、纯色背景、柔和均匀光 |

用户没指定画风时，**按交付场景选一个合理的默认**，并在回复里说明你选了什么，给他改的机会：

- 图标 / 线稿 → 线条
- 贴纸 / 可爱 → 卡通
- 海报 / 封面 → 平面
- 产品图 / 人像 → 摄影

## 第四步：写成提示词

这是**检查表不是模板** —— 顺序与详略跟着媒介走，也可以按需要加轴：

1. **主体与动作** —— 画的是什么，在做什么。
2. **媒介与画风** —— 用那种媒介自己的词汇。
3. **构图与取景** —— 景别、角度、视线引导。
4. **色彩与影调** —— 调色板、明暗、氛围。
5. **细节与质感** —— 材质、纹理。
6. **画面内文字** —— 逐字给出，注明大小写与拼写。

用**具体的名词和参数**，不要写「高级 / 大气 / 好看」这类空词。

## 画幅与尺寸：写进 prompt，不要传参数

对话里提到的**画幅比例或图片尺寸**（「竖的」「9:16」「2K」）**写进 prompt** —— 这是它们进入请求的唯一通道：

- 「要 9:16」→ `vertical 9:16 portrait format, tall framing`
- 「用 2K」→ `high-detail 2K render`

同时**不要**填 `aspect_ratio` / `resolution` 参数 —— 那两个字段归工作台的「参数」面板，你看不到面板的值，猜一个填进去只会和它打架。

用户没提画幅时，**按这句话的意图写构图，不要猜他的面板** —— prompt 不写比值。

prompt 里照写了比值时，回复里提醒一句「面板宽高比可设为 9:16」，两条路都不断。

## 其余参数值不要写进 prompt

**只有会改变画面本身的信息值得进 prompt。**

- `seed 12345`、`high quality`、`2 张` 都是字段值，不是画面内容。
- 用户说「要透明底」→ **干脆别描述背景**（不写台面、地面、投影），背景走 `background` 字段。
- 数量 / 画质 / 种子 / 格式永远靠 API 字段。

## 参考图的三种给法

1. **用户在对话里贴的图** —— 已经在附件里，直接用。
2. **`reference_files`** —— 本机绝对路径，**必须位于会话工作目录内**（越界会被拒绝）；Host 会读出来内联。
3. **`reference_images`** —— http(s) URL 或 data URL，最多 4 张。

带参考图时，提示词**只写要改的部分与新场景**（背景、光线、镜头、风格、构图），不要复述参考图里已有的外观。

> **注意**：如果 `vision-router` 之类的插件把附图先转成了**文字描述**喂给你，那段描述**不应该**被抄进提示词 —— 那是给你看的，不是给生图模型的。

## 迭代与排错

- **改图后主体变形了** → 提示词里多半复述了主体外观，删掉那些描述，只留改动点。
- **画风不对，像照片** → 检查是不是写进了焦段、光圈、柔光箱、色温；把它们删掉。
- **画风不对，太扁平** → 检查是不是把摄影的轴删过头了；补回该媒介真正需要的细节轴。
- **要复现同一张** → 用 `seed` 字段固定种子，而不是把数字写进 prompt。
- **一次出多张** → 用 `count` 字段；想比较不同构图就改提示词分次出。
